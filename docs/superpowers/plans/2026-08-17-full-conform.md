# Full Conform Implementation Plan (P06)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Retire the embedded `init/` engine: the blueprint's only rebrand engine becomes the released external press, CI drift detection becomes `press verify`, and the press config gains the v3.6.0 features the dogfoods earned.

**Architecture:** One campaign branch (`feat/full-conform` in `~/c/py-launch-blueprint-p06`), one PR — a fork pressed from any merged state must never see half-migrated docs, so config upgrade, cutover, deletion, and doc rewrites land together. Exit codes are the assertions throughout.

**Tech Stack:** released `template-press>=3.6.0` via `uvx` (never a git pin), TOML config, POSIX shell (guard), GitHub Actions, lefthook.

**Spec:** `docs/superpowers/specs/2026-08-17-full-conform-design.md` (committed `2d11ba2` on this branch).

## Global Constraints

- **Press-under-conform:** `uvx --from 'template-press>=3.6.0' press …` everywhere (CI, hooks, docs). Local dev iteration may use `uv run press` from `~/c/template-press` main, but every committed reference is the released uvx form. **Blocked until the v3.6.0 tag + PyPI publish confirm** (in flight).
- **Distinct file sets — never conflate:** files the blueprint DELETES for itself this campaign (`init/`, the two legacy workflows) versus files the blueprint KEEPS but declares `[[remove]]` so FORKS drop them (dogfood docs, TUI design, prototypes, `update-contributors.yml`).
- Conventional commits, lowercase; merge queue on main; bots re-review every push (batch fixes); GitHub polling ≥20s REST.
- Findings continue the dogfood log as **Run 5**, numbering from PROBLEM-29.
- Task 6's acceptance bar: ZERO hand-fixes of the P05 classes (inherited workflows, snapshots, pre-push gates).
